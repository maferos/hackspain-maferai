# sink

A lab sink with one gooseneck tap centred on the basin, **1.502 m (X) × 0.754 m (Y) × 1.281 m (Z)**, worktop
at 0.92 m, tap on the +Y edge.

Everything except `3d-model.3ds.zip` (the vendor download) is generated by
[`tools/convert_3ds.py`](../../tools/convert_3ds.py); re-run it rather than editing the files:

```bash
unzip -o assets/sink/3d-model.3ds.zip -d /tmp/sink
python tools/convert_3ds.py /tmp/sink/3d-model.3ds --name sink --scale 0.0254 --out assets/sink \
    --skip-node 4 --center-x 3 \
    --recolor Translucent_Glas=0.93,0.92,0.88 Color_I13=0.92,0.92,0.91
    # inches; one tap, centred; white resin top and white frame instead of the vendor's green/blue
```

`--list` prints the nodes. The vendor model has two taps (nodes 3 and 4, the second an
instance of the first); we keep node 3 and move it onto the basin's centre line.

The .3ds places its parts through the keyframer (the second tap is an instance, the
first tap and the drain trap are mirrored nodes). The converter applies those transforms
and flips the winding of mirrored nodes, so each part lands where it belongs.

## Frame convention

Origin on the floor, centred in X and Y, +Z up. Place it at `z = 0`.

## Files

| File | Purpose |
| --- | --- |
| `sink.xml` | MJCF: mesh visuals (no collision) + one box collider over the whole sink |
| `part_00.obj` … `part_05.obj` | One mesh per material, metres |
| `3d-model.3ds.zip` | Vendor source |

`sink.xml` has a single `sink` body, so attach it (not `<include>`) to place several:

```xml
<asset><model name="sink" file="../assets/sink/sink.xml"/></asset>
...
<frame pos="4.051 0 0"><attach model="sink" body="sink" prefix="right_"/></frame>
```

See `models/minihannover_scene.xml`.
